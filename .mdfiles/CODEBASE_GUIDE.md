## B. File-by-file guide

Files are grouped by how much they control behaviour. **Tier 1** = read closely before changing anything; **Tier 2** = important supporting code; **Tier 3** = small or rarely changed.

### Tier 1 — the chat path

#### `backend/app/main.py`
- **Purpose:** create the FastAPI `app`, start/stop the MCP session, log requests, define the 5 routes.
- **Key names:** `lifespan()`, `app`, `request_logging()`, `health()`, `ready()`, `chat()`, `feedback()`, `safeguarding_confirm()`.
- **Imported by:** uvicorn (`app.main:app`), tests (`tests/test_api.py`, integration tests), probe scripts.
- **Imports/calls:** `config.settings`, `models.*`, `mcp.client.start/stop_persistent_session`, `observability.start_trace/get_trace`, `services.advisor.process_chat/check_ollama_available`, `services.feedback.record_feedback`, `services.readiness.*`, `services.safeguarding.confirm_safeguarding`.
- **In/out:** HTTP requests → JSON responses (validated by `response_model`).
- **Side effects:** spawns the MCP child at startup; logs every request.
- **Before modifying:** route functions are *framework hooks* — FastAPI calls them; keep heavy logic in `services/`. CORS only allows `GET, POST, OPTIONS` and the `Content-Type` header.

#### `backend/app/models.py`
- **Purpose:** the API contract.
- **Key names:** `Audience`, `AgeBand`, `RiskLevel` (enums); `ChatRequest`, `Citation` (alias `SourceCitation`), `ChatResponse` (with validator `_sync_sources_alias`), `FeedbackRequest`, `SafeguardingConfirmRequest`, `SafeguardingConfirmResponse`, `HealthResponse`, `ReadyResponse`.
- **Imported by:** almost every backend module and the routing/agent code.
- **Before modifying:** any field change must be mirrored in `advisorApi.js`/`useAdvisorChat.js`/`AssistantResponse.js` (no shared types). Full field list: [REQUEST_LIFECYCLE.md §D](REQUEST_LIFECYCLE.md#d-actual-request-and-response-schemas).

#### `backend/app/services/advisor.py`
- **Purpose:** the chat pipeline for one turn.
- **Key names:** `process_chat(request, use_ollama=True)`, `check_ollama_available()` (cached 15 s, shared `httpx.AsyncClient` from `_ollama_client()`), `_escalation_response()`.
- **Called by:** `main.py::chat`, `scripts/profile_chat_latency.py`, tests.
- **Calls:** `session_store.resolve/append`, `safety.classify_safety`, `agent.prepare_context`, `agent.run_advisor_agent`, `agent.run_fallback_via_mcp`, `citations.strip_model_sources_section`.
- **Side effects:** session writes; HTTP to Ollama `/api/tags`.
- **Before modifying:** the **order** matters: session → safety → context → agent/fallback. Never move the safety check after the agent. Errors in the agent are swallowed into a `degraded` answer here.

#### `backend/app/safety.py`
- **Purpose:** deterministic risk gate.
- **Key names:** `SafetyResult`, `URGENT_PATTERNS` (8 categories), `REFERRAL_PATTERNS` (4), `URGENT_ESCALATION_MESSAGE`, `REFERRAL_MESSAGE`, `classify_safety(message)`.
- **Called by:** `process_chat`, safety tests.
- **Before modifying:** run `pytest tests/test_safety.py tests/test_safety_metrics.py`; add new phrases to `backend/eval/prompts.json` (urgent prompts must stay urgent; `benign_keywords` must stay normal). See DECISIONS DEC-002.

#### `backend/app/agent.py`
- **Purpose:** build the turn's context, run the LangChain agent, assemble the result, and the template fallback.
- **Key names:** `AGENT_TOOL_NAMES`, `FOLLOW_UP_TEMPLATES`, `TurnContext`, `AdvisorResult`, `prepare_context()`, `_retrieval_query()`, `_passages_block()`, `_build_user_message()`, `chat_ollama_kwargs()`, `_agent_cache_key()`, `_compiled_advisor_agent()`, `trim_history_messages()`, `run_advisor_agent()`, `_resolve_citations()`, `_log_agent_tool_activity()`, `_collect_activity_plan_from_messages()`, `_last_ai_text()`, `_follow_up()`, `_infer_topic()`, `_extract_actions_from_snippets()`, `run_fallback_via_mcp()`.
- **Called by:** `services/advisor.py`, tests.
- **Calls:** `routing.detect_intent`, `services.retrieval.fetch_citations_via_mcp`, `mcp_client.invoke_mcp_tool/get_mcp_tools`, LangChain `create_agent` + `ChatOllama`, `citations.*`, `prompts.*`, `ollama_profile.*`.
- **Side effects:** model calls (HTTP to Ollama), tool calls (MCP), trace/log updates; caches one compiled agent per process.
- **Before modifying:** the prompt is assembled in `_build_user_message` (per turn) + `prompts.SYSTEM_PROMPT` (fixed at compile time — changing it needs a restart because the agent is cached). Keep `submit_safeguarding_flag` out of `AGENT_TOOL_NAMES`.

#### `backend/app/mcp/client.py`
- **Purpose:** talk to the MCP server.
- **Key names:** `SERVER_NAME`, `MCP_SERVER_SCRIPT`, `EXPECTED_TOOLS`, `get_mcp_client()`, `start_persistent_session()`, `stop_persistent_session()`, `_disable_persistent_tools()`, `using_persistent_session()`, `get_mcp_tools()`, `_get_per_call_tools()`, `_call()`, `invoke_mcp_tool()`, `_result_metadata()`.
- **Called by:** `main.lifespan`, `agent.py` (via the `app/mcp_client.py` re-export), `services/retrieval.py`, `services/safeguarding.py`, `services/readiness.py`.
- **Side effects:** spawns and owns the child process; logs `MCP_TOOL_RESULT`.
- **Before modifying:** the persistent session must be opened and closed **in the same task** (the lifespan). `invoke_mcp_tool` never raises — it returns `{"error": ...}`.

#### `backend/mcp_server/server.py`
- **Purpose:** the tool process: list tools and dispatch calls.
- **Key names:** `server = Server("advisor-tools")`, `TOOL_INPUT_MODELS`, `TOOL_HANDLERS`, `TOOL_DESCRIPTIONS`, `_validate_arguments()`, `list_tools()` (decorated `@server.list_tools()`), `call_tool()` (decorated `@server.call_tool()`), `main()`.
- **Started by:** the MCP client (never by the API importing it). You *can* run `python backend/mcp_server/server.py` by hand to see import errors (it will then wait for JSON-RPC on stdin).
- **Before modifying:** a new tool needs an entry in all three dicts plus a Pydantic input model in `tool_inputs.py`. Errors are returned as `{"error": ...}` JSON text, not MCP `isError`.

#### `backend/mcp_server/tools/search_knowledge.py`
- **Purpose:** vector search.
- **Key names:** `COLLECTION_NAME = "advisor_kb"`, `_get_collection()` (cached client), `reset_collection_cache()` (unused), `_collection_count()` (30 s cache), `_build_where_clause()` (topics only), `search_knowledge(query, topics=None, max_results=4)`.
- **Called by:** MCP `call_tool`; `readiness.check_chroma` imports `_get_collection`; tests.
- **Side effects:** HTTP to Ollama (embed); Chroma disk reads.
- **Before modifying:** distance cutoff = `settings.chroma_max_distance`; result row fields feed `citations.citation_from_retrieval_hit`.

## C. Function and class relationships

Legend: **calls** = our code calls it directly · **hook** = a framework calls it · **callback** = called by a library during another call · **import-only** = shares a definition, no call.

```
uvicorn ──hook──▶ main.lifespan ──calls──▶ mcp.client.start_persistent_session ──spawns──▶ mcp_server/server.py::main
FastAPI ──hook──▶ main.request_logging ──▶ (next) ──hook──▶ main.chat
main.chat ──calls──▶ observability.start_trace
          ──calls──▶ services.advisor.process_chat
process_chat ──calls──▶ SessionStore.resolve / append
             ──calls──▶ safety.classify_safety
             ──calls──▶ check_ollama_available
             ──calls──▶ agent.prepare_context ──calls──▶ routing.detect_intent ──calls──▶ plan_params.extract_activity_plan_params
                                             ──calls──▶ services.retrieval.fetch_citations_via_mcp ──calls──▶ mcp.client.invoke_mcp_tool
                                             ──calls──▶ invoke_mcp_tool("get_school_policy" | "create_activity_plan")
             ──calls──▶ agent.run_advisor_agent ──calls──▶ get_mcp_tools, _compiled_advisor_agent, _build_user_message
                                                ──calls──▶ agent.ainvoke ──(LangGraph)──▶ ChatOllama ⇒ Ollama
                                                                         ──(LangGraph ToolNode)──▶ MCP BaseTool.ainvoke ⇒ server.call_tool
                                                ──callback── OllamaProfileHandler.on_chat_model_* / on_tool_*
                                                ──calls──▶ _resolve_citations ──calls──▶ citations.*
             ──calls──▶ agent.run_fallback_via_mcp (on failure) ──calls──▶ prompts.build_fallback_response
server.call_tool ──calls──▶ _validate_arguments ──▶ TOOL_HANDLERS[name] (dict lookup = dynamic dispatch)
                                                    ──▶ tools.search_knowledge ──calls──▶ embeddings.embed_query ⇒ Ollama; Chroma query
                                                    ──▶ tools.activity_plan.create_activity_plan ──calls──▶ _expand_steps
                                                    ──▶ tools.school_policy.get_school_policy ──calls──▶ tenant.trusted_school_id, _load_policy_file
                                                    ──▶ tools.safeguarding.submit_safeguarding_flag
```

Import-only relationships worth knowing:
- `routing.py` **imports** `ActivityGoal`/`PolicyType` from `mcp_server/tool_inputs.py` (API depends on the server's schema module).
- The MCP child **imports** `app.config`, `app.embeddings`, `app.tenant` — the "separate" process shares code and settings with the API.
- `readiness.check_chroma` **imports and calls** `mcp_server.tools.search_knowledge._get_collection` inside the API process.
- `ChatResponse._sync_sources_alias` is a Pydantic **validator hook**: runs automatically when a `ChatResponse` is built.

Frontend relationships:

```
ERP router ──hook──▶ AdvisorPage ──renders──▶ ChildConnectApp ──hook──▶ useAdvisorChat
ChatInput.handleSubmit ──calls(prop)──▶ ChildConnectApp.handleSubmit ──calls──▶ sendMessage ──calls──▶ advisorApi.sendChatMessage ──calls──▶ advisorFetch ⇒ fetch
React re-render ──▶ ChatWindow ──▶ ChatMessage ──▶ AssistantResponse ──▶ MarkdownText(parseMarkdown) / ActivityPlan / SourcesList / SafeguardingConfirm / FeedbackControls
```

Detailed call chains with inputs/outputs: [FLOW.md §6](FLOW.md#6-function-by-function-call-chains).

## E. Configuration and startup

### Backend settings (`backend/app/config.py::Settings`)

Read from environment variables or `backend/.env` (names are case-insensitive). **Values are not shown here**; see `backend/.env.example` for documented defaults. Both the API process and the MCP child read the same file.

| Variable | Default in code | Read in / affects |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | `agent.chat_ollama_kwargs`, `embeddings.get_embedding_model`, `services/advisor.check_ollama_available` |
| `OLLAMA_CHAT_MODEL` | `qwen3.8:latest` | `chat_ollama_kwargs` — which model writes answers |
| `OLLAMA_EMBED_MODEL` | `nomic-embed-text` | `embeddings.py`; stored as collection metadata by `ingest.py`. **Changing it requires re-ingest.** |
| `CHROMA_PATH` | `backend/data/chroma` (absolute) | `search_knowledge._get_collection`, `ingest.get_client`. `.env.example` uses `./data/chroma`, which is **relative to the current directory** — start uvicorn and ingestion from `backend/` *(inferred gotcha)*. |
| `CHROMA_MAX_DISTANCE` | `0.9` | `search_knowledge` cutoff |
| `KB_VERSION` | `0.1.0` | FastAPI version, `/api/health`, search results, ingest metadata |
| `SCHOOL_ID` | `poc_test_school` | `tenant.trusted_school_id` → policy file name; prompt text |
| `CORS_ORIGINS` | `http://127.0.0.1:5173` | `main.py` CORS middleware (comma-separated) |
| `MAX_AGENT_STEPS` | `8` | LangGraph `recursion_limit` |
| `MCP_PYTHON_COMMAND` | empty → `sys.executable` | interpreter used to start the MCP child |
| `SESSION_MAX_MESSAGES` / `SESSION_TTL_SECONDS` / `SESSION_MAX_SESSIONS` | `12` / `3600` / `500` | `sessions/store.py` |
| `SESSION_AGENT_HISTORY` / `HISTORY_MESSAGE_CHARS` | `6` / `1500` | `agent.trim_history_messages` |
| `OLLAMA_NUM_PREDICT` / `OLLAMA_NUM_CTX` / `OLLAMA_KEEP_ALIVE` / `OLLAMA_REASONING` | `896` / `8192` / `30m` / `False` | `chat_ollama_kwargs` |
| `AUDIT_DIR` | `backend/data/audit` | `services/feedback.py`, `tools/safeguarding.py` (tests set a temp dir) |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `8787` | **Not used** — uvicorn's `--host/--port` flags decide |

Other configuration, outside `config.py`:
- **Ollama's own `OLLAMA_MODELS`** (machine-wide on this server) decides which model folder Ollama reads — see DECISIONS R24.
- **ERP side:** `ADVISOR_BACKEND_URL` (read by `registerAdvisorProxy.js::getBackendBase`; the live ERP reportedly reads the same name — unverified) and `api.base_url` in the ERP's `config_web.json` (read by `advisorApi.js` via `getConfig()`).
- **Optional LangSmith:** README mentions `LANGCHAIN_TRACING_V2` / `LANGCHAIN_API_KEY`; no project code reads them (LangChain would pick them up itself — inferred).

### Starting things (commands supported by README and scripts)

```bash
# one-time (backend/)
python -m venv .venv            # then activate
pip install -r requirements.txt
python -m ingestion.ingest       # build data/chroma (add --reset to rebuild)

# run API (backend/)
uvicorn app.main:app --host 127.0.0.1 --port 8787 --reload

# dev UI (reference_frontend/) — http://127.0.0.1:5173
npm install
npm run dev

# both at once (repo root)
scripts/run_dev.ps1      # or: bash scripts/run_dev.sh

# tests (backend/)
pytest tests --ignore=tests/integration     # no services needed
pytest tests/integration                    # needs Ollama + Chroma
```

**How the frontend reaches the backend:** ERP page → `{api.base_url}/api/advisor/*` on the ERP server → forwarded to the Advisor API (production). Dev UI → `/api/*` on the Vite server → Vite proxy → `http://127.0.0.1:8787` (local). The older `src/Pages/AdvisorPage.js` called `:8787` from the browser directly — that approach is retired.

## F. Debugging map

Start with the first column; move right if it looks fine. Every backend log line carries `request_id=…`. A fuller symptom table is in [FLOW.md §14](FLOW.md#14-debugging-guide).

| Symptom | First look | Next | Then |
|---|---|---|---|
| Nothing sent | `ChatInput.js::handleSubmit` (empty/`loading`) | `useAdvisorChat.js::sendMessage` (`loadingRef`) | browser Network tab; `advisorApi.js` base URL |
| HTTP 401/403/503 | ERP proxy (not in repo) | `advisorApi.js::friendlyHttpError` | is uvicorn running on the URL the proxy uses? |
| HTTP 422 | response `detail` field list | `models.py::ChatRequest` constraints | payload built in `useAdvisorChat.js` |
| HTTP 500 | uvicorn traceback | the route in `main.py` | `services/feedback.py` file permissions |
| "AI advisor is unavailable" / `degraded: true` | log `Ollama or context unavailable` / `Agent pipeline failed` | `curl {OLLAMA_BASE_URL}/api/tags`; Ollama log (model load) | `agent.py::run_advisor_agent` exception |
| Slow replies | `CHAT_COMPLETE timings_ms` (`prepare_context`, `agent_ainvoke`) | `OLLAMA_PROFILE_SUMMARY` | `MCP_TOOL_RESULT persistent=False` → per-call mode |
| No sources / wrong sources | `CONTEXT_READY hits=` | `search_knowledge` logs (`error`, `total_chunks`) | `CHROMA_MAX_DISTANCE`, embed model, ingestion |
| Policy invented or missing | `CONTEXT_READY policy=` | `routing.py::detect_policy` | `school_policy.py`, policy JSON keys |
| Plan missing | `CONTEXT_READY plan=` | `routing.py::is_plan_request` / `plan_goal` | `activity_plan.py`; UI `ActivityPlan.js` |
| MCP errors | startup `MCP_PERSISTENT_SESSION started` | `MCP_TOOL_RESULT` / "switching to per-call mode" | run `python mcp_server/server.py` manually for import errors |
| Answer not shown | `advisorApi.js::sendChatMessage` shape check | `useAdvisorChat.js` state update | browser console (React errors in `AssistantResponse`/`MarkdownText`) |
| Urgent message not escalated / benign one escalated | `safety.py::classify_safety` | `eval/prompts.json` | `tests/test_safety_metrics.py` |
